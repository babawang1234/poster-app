## 修复并启动「幻象工坊」网站

### 问题
服务无法启动，连续报三类错误：
1. `bash.exe: could not find /tmp` + `shell-runtime-bash-env.sh: Permission denied` → Bash 运行时环境故障
2. `NODE_OPTIONS` 注入的 shim 路径已失效 → `EPERM: open 'D:\workbuddy\resources\app.asar.unpacked\cli\vendor\shim\node-language-shim.cjs'`
3. 后台任务模式下 node 读项目文件被沙箱拒绝（`EPERM open src/index.js`）

### 根因
- WorkBuddy 升级后，shim 目录从 `cli/vendor/shim` 迁到 `cli/vendor/sandbox-center-runtime-kit/shim`，
  但宿主仍注入指向旧路径的 `NODE_OPTIONS`，node 加载即失败。
- 沙箱在此期间出现 `center 规则快照不可用` 的临时故障，影响 Bash/PowerShell 后台任务。

### 解决
- 启动命令前置清空变量：`NODE_OPTIONS= node src/index.js`，前后端分别启动，绕过 concurrently 的 `spawn cmd.exe ENOENT`。
- 新增一键脚本 `scripts/start-dev.sh` / `scripts/start-dev.ps1`，内置 NODE_OPTIONS 清理与依赖检查。
- 服务恢复正常：前端 5173、后端 4000；自检 health 200 / 模板列表 200 / 未登录 401 符合预期。

### 备注
- 本地请求不要用 curl（会被失效的 2266 代理劫持），改用 node fetch。

## 云端部署（sites）关键坑
- **同一会话/工作区内，workbuddy_sites_deploy 永远指向同一个 app（sandboxId 相同）**。
  给子目录（如 scraper-service）或兄弟目录部署，会直接覆盖主应用沙箱 → 网站被换成 Python 服务，
  首页返回 `{"detail":"Not Found"}`。恢复办法：重新发布网站根目录。
  要第二个独立应用，必须另开新任务/新工作区再发布。
- 云沙箱 Python < 3.12，requirements 不要 pin `>=3.12` 才能装的新版本（websockets/anyio 等），
  否则 SITES_INSTALL_FAILED。用无版本声明让 pip 自行解析。
- 分享链接有访问控制：不带 `?sharecode=` 的 API 请求返回 403「链接不完整」，
  浏览器首次带 sharecode 会拿到 cookie，后续同域请求正常。
- 单端口部署改造：server/src/index.js 已加 client/dist 静态托管 + SPA 回退，listen 绑 0.0.0.0。
  生产流程＝`npm install && npm run build` → `node server/src/index.js`。
- 云上 SQLite 随代码上传，**重新发布会把数据回滚到上传时的状态**；正式上线前须迁云数据库。

## 云端认证排查结论
- 云端 401「登录已过期」**不是密钥问题**：用本地 `config.jwt.secret` 可成功 verify 云端签发的 token，
  说明 JWT_SECRET 两端一致。旧代码 authRequired 把 DB 异常也 catch 成「登录已过期」，误导排查。
- 分享链接有网关级校验：不带 `?sharecode=` / cookie 的请求一律 403「链接不完整」（平台页面，非应用返回）。
  因此**自动化脚本无法完整模拟浏览器会话**，云端功能验证应以用户实际浏览器访问为准。
- 抓取能力最终用 **Node 内置实现**（server/src/lib/scraper.js，cheerio 解析），
  放弃独立 Python 服务（单端口 + 同会话只能一个应用）。
  接口：GET /api/assets/scraper-status、POST /api/assets/scrape（需登录）。
  护栏：robots.txt、内网拦截、域名白名单、同域限速 1.5s、超时、体积上限。
- 前端尚未加「从网址抓取」入口 UI，目前只有后端接口。
